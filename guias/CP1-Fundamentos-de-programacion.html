Módulo 1

¿Qué es Programar?

Darle instrucciones exactas a una máquina que obedece al pie de la letra... y no entiende indirectas.

🍰 La analogía de la receta

Imagina que le explicas a alguien que nunca ha cocinado cómo hacer un pastel. No puedes decir "hornéalo hasta que esté listo": debes decir "hornea a 180°C durante 35 minutos". Una computadora es ese aprendiz extremo: hace exactamente lo que le dices, ni más ni menos.

Programar es...

Escribir instrucciones paso a paso (un algoritmo🇪🇸 Algoritmo / 🇺🇸 Algorithm — Serie de pasos ordenados y finitos para resolver un problema. Una receta de cocina es un algoritmo.) que una computadora puede ejecutar.

Un programa es...

Ese conjunto de instrucciones ya escrito en un lenguaje de programación🇪🇸 Lenguaje de Programación / 🇺🇸 Programming Language — Idioma formal con reglas estrictas (sintaxis) que humanos usan para escribir instrucciones que una computadora puede ejecutar., listo para ejecutarse.

El código fuente es...

El texto que escribes. Como el manuscrito de la receta antes de que alguien la cocine.

Tu primer programa: Hola Mundo

Por tradición, el primer programa de todo programador muestra el texto "Hola Mundo" en pantalla. Compara ambos lenguajes:

# Python: una sola línea. print() muestra texto en pantalla
print("¡Hola Mundo!")
// C# moderno (top-level statements): también una línea
Console.WriteLine("¡Hola Mundo!");
⚠️ Observa las diferencias: en C# cada instrucción termina con punto y coma ; y las funciones viven dentro de clases (Console). En Python el formato es más ligero. Pero la idea es idéntica: darle una orden a la máquina.

Compilado vs. Interpretado

📖 Interpretado (Python)

Un intérprete🇪🇸 Intérprete / 🇺🇸 Interpreter — Programa que lee y ejecuta el código fuente línea por línea, sin generar un archivo ejecutable previo. lee tu código línea por línea y lo va ejecutando al momento.

Analogía: un traductor simultáneo en una conferencia — traduce mientras hablas.

  • ✅ Rápido para probar ideas
  • ✅ Corre igual en Windows, Mac, Linux
  • ❌ Más lento al ejecutar
  • ❌ Algunos errores aparecen hasta que esa línea corre

⚙️ Compilado (C#)

Un compilador🇪🇸 Compilador / 🇺🇸 Compiler — Programa que traduce TODO el código fuente a un formato ejecutable antes de correrlo, detectando errores de sintaxis y tipos en el proceso. traduce todo el programa completo antes de ejecutarlo (en C#, a un lenguaje intermedio llamado IL que corre sobre .NET).

Analogía: traducir un libro completo antes de publicarlo.

  • ✅ Detecta muchos errores ANTES de ejecutar
  • ✅ Ejecución más rápida
  • ❌ Hay que compilar en cada cambio
  • ❌ Un poco más de "ceremonia" para empezar

Pensar antes de escribir: el pseudocódigo

El pseudocódigo🇪🇸 Pseudocódigo / 🇺🇸 Pseudocode — Descripción de un algoritmo en lenguaje humano estructurado, sin la sintaxis estricta de un lenguaje real. Sirve para planear antes de programar. es escribir la lógica en español estructurado antes de escribir código real. Los programadores senior planean primero y escriben código después.

ALGORITMO: ¿puedo comprar el producto?

1. LEER precio del producto

2. LEER dinero disponible

3. SI dinero >= precio ENTONCES

MOSTRAR "Puedes comprarlo"

4. SI NO

MOSTRAR "Te falta dinero"

Las 4 fases para resolver cualquier problema

  1. 1Entender: ¿qué entra, qué debe salir? Si no puedes explicarlo con palabras, no puedes programarlo.
  2. 2Planear: escribe el pseudocódigo o dibuja el flujo.
  3. 3Codificar: traduce el plan al lenguaje (Python, C#...).
  4. 4Probar y corregir: ejecuta con distintos casos, incluidos los raros (¿y si el precio es 0?).

Variables y Tipos de Datos

Las cajas etiquetadas donde tu programa guarda información.

📦 La analogía de la caja etiquetada

Una variable🇪🇸 Variable / 🇺🇸 Variable — Espacio en memoria con un nombre, donde el programa guarda un valor que puede cambiar durante la ejecución. es una caja con una etiqueta: la etiqueta es el nombre (edad) y dentro va el valor (25). Puedes cambiar el contenido cuando quieras — por eso se llama variable. El tipo de dato🇪🇸 Tipo de Dato / 🇺🇸 Data Type — Categoría del valor que define qué operaciones se pueden hacer con él: número entero, decimal, texto, booleano, etc. dice qué clase de cosa cabe en la caja: números, texto, verdadero/falso...

# Python decide el tipo automáticamente (tipado dinámico)
nombre = "Nayeli"       # str    → texto
edad = 28                # int    → número entero
estatura = 1.65          # float  → número decimal
es_estudiante = True     # bool   → verdadero o falso

print(f"Hola {nombre}, tienes {edad} años")
// En C# declaras el tipo ANTES del nombre (tipado estático)
string nombre = "Nayeli";      // texto
int edad = 28;                 // número entero
double estatura = 1.65;        // número decimal
bool esEstudiante = true;      // verdadero o falso

Console.WriteLine($"Hola {nombre}, tienes {edad} años");

💡 Ambos lenguajes tienen interpolación de cadenas: f"..." en Python y $"..." en C# permiten insertar variables dentro del texto con llaves {}.

Operadores: hacer cosas con los valores

Aritméticos

  • + suma · - resta
  • * multiplicación · / división
  • % módulo (residuo de dividir)
  • ** potencia (Py) · Math.Pow (C#)
  • // división entera (Py)

Comparación

  • == igual · != diferente
  • > mayor · < menor
  • >= mayor o igual
  • <= menor o igual
  • Siempre devuelven un booleano

Lógicos

  • Py: and, or, not
  • C#: &&, ||, !
  • and: ambas verdaderas
  • or: al menos una verdadera
  • not: invierte el valor
🚨 Error clásico de principiante: confundir = (asignar un valor) con == (comparar si son iguales). edad = 18 guarda 18 en la caja; edad == 18 pregunta "¿la caja contiene 18?".

Conversión de tipos (casting)

Lo que el usuario escribe siempre llega como texto. Para hacer matemáticas hay que convertirlo🇪🇸 Conversión de tipos / 🇺🇸 Type Casting — Transformar un valor de un tipo a otro, por ejemplo el texto "25" al número 25.:

texto = "25"            # esto es TEXTO, no un número
numero = int(texto)     # ahora sí es el número 25
precio = float("9.99")  # texto → decimal
etiqueta = str(100)     # número → texto "100"

# Sin convertir: "25" + "5" = "255" (une textos!)
# Convertido:     25 + 5   = 30
string texto = "25";                // esto es TEXTO
int numero = int.Parse(texto);       // ahora es el número 25
double precio = double.Parse("9.99");
string etiqueta = 100.ToString();    // número → texto

// Versión segura: no truena si el texto no es número
bool ok = int.TryParse(texto, out int resultado);

Módulo 3

Control de Flujo

Enseñarle al programa a tomar decisiones y a repetir tareas.

🚦 Decisiones: if / else

Un programa sin decisiones siempre hace lo mismo. El condicional🇪🇸 Condicional / 🇺🇸 Conditional — Estructura que ejecuta un bloque de código solo si una condición es verdadera (if), con alternativas (else if / else). if es una bifurcación en el camino: "SI llueve, lleva paraguas; SI NO, lleva lentes de sol".

temperatura = 35

if temperatura > 30:
    print("Hace calor 🥵")
elif temperatura > 15:          # "elif" = else if
    print("Clima agradable 😊")
else:
    print("Hace frío 🥶")

# OJO: en Python la indentación (4 espacios) DEFINE el bloque
int temperatura = 35;

if (temperatura > 30)
{
    Console.WriteLine("Hace calor 🥵");
}
else if (temperatura > 15)
{
    Console.WriteLine("Clima agradable 😊");
}
else
{
    Console.WriteLine("Hace frío 🥶");
}
// En C# las llaves { } definen el bloque, y la condición va entre ( )

💡 Las condiciones se evalúan en orden y solo entra al primer bloque verdadero. Si temperatura fuera 35, nunca revisa el elif.

Muchos casos: switch / match

Cuando comparas una misma variable contra muchos valores, hay una estructura más limpia que encadenar diez if:

dia = "sábado"

match dia:                    # match existe desde Python 3.10
    case "sábado" | "domingo":
        print("¡Fin de semana!")
    case "viernes":
        print("Casi...")
    case _:                   # _ = cualquier otro caso (default)
        print("Día laboral")
string dia = "sábado";

switch (dia)
{
    case "sábado":
    case "domingo":
        Console.WriteLine("¡Fin de semana!");
        break;
    case "viernes":
        Console.WriteLine("Casi...");
        break;
    default:
        Console.WriteLine("Día laboral");
        break;
}

Repeticiones: los bucles

🔁 for — "repite N veces / por cada elemento"

Úsalo cuando sabes cuántas veces repetir, o cuando quieres recorrer una colección elemento por elemento. Analogía: repartir un volante a cada casa de la cuadra.

♾️ while — "repite MIENTRAS sea cierto"

Úsalo cuando no sabes cuántas veces: depende de una condición. Analogía: seguir batiendo la mezcla mientras tenga grumos. ⚠️ Si la condición nunca se vuelve falsa → bucle infinito🇪🇸 Bucle Infinito / 🇺🇸 Infinite Loop — Bucle cuya condición nunca se vuelve falsa, por lo que el programa se queda atorado repitiendo para siempre..

# FOR: repetir 5 veces (range genera 0,1,2,3,4)
for i in range(5):
    print(f"Vuelta número {i}")

# FOR: recorrer una lista elemento por elemento
frutas = ["manzana", "pera", "uva"]
for fruta in frutas:
    print(fruta)

# WHILE: repetir mientras la condición sea verdadera
vidas = 3
while vidas > 0:
    print(f"Te quedan {vidas} vidas")
    vidas = vidas - 1   # ¡sin esta línea sería infinito!
// FOR: repetir 5 veces (inicio; condición; incremento)
for (int i = 0; i < 5; i++)
{
    Console.WriteLine($"Vuelta número {i}");
}

// FOREACH: recorrer una lista elemento por elemento
var frutas = new List<string> { "manzana", "pera", "uva" };
foreach (string fruta in frutas)
{
    Console.WriteLine(fruta);
}

// WHILE: repetir mientras la condición sea verdadera
int vidas = 3;
while (vidas > 0)
{
    Console.WriteLine($"Te quedan {vidas} vidas");
    vidas--;   // vidas-- resta 1 (¡sin esto sería infinito!)
}
break — sal del bucle inmediatamente. "Encontré las llaves, dejo de buscar."
continue — salta a la siguiente vuelta. "Esta casa no tiene buzón, sigo con la siguiente."

Ejercicio clásico de entrevista: FizzBuzz

Imprime los números del 1 al 15; pero si es múltiplo de 3 imprime "Fizz", si es múltiplo de 5 "Buzz" y si es de ambos "FizzBuzz". Combina todo lo del módulo:

for n in range(1, 16):          # del 1 al 15
    if n % 3 == 0 and n % 5 == 0:   # % = residuo. Si es 0, es múltiplo
        print("FizzBuzz")
    elif n % 3 == 0:
        print("Fizz")
    elif n % 5 == 0:
        print("Buzz")
    else:
        print(n)
for (int n = 1; n <= 15; n++)
{
    if (n % 3 == 0 && n % 5 == 0)   // % = residuo. Si es 0, es múltiplo
        Console.WriteLine("FizzBuzz");
    else if (n % 3 == 0)
        Console.WriteLine("Fizz");
    else if (n % 5 == 0)
        Console.WriteLine("Buzz");
    else
        Console.WriteLine(n);
}

Módulo 4

Funciones

Escribe la lógica una vez, úsala mil veces.

☕ La analogía de la cafetera

Una función🇪🇸 Función / 🇺🇸 Function — Bloque de código con nombre que realiza una tarea específica. Recibe entradas (parámetros) y puede devolver una salida (return). es como una cafetera: le pones entradas (agua y café molido = parámetros🇪🇸 Parámetro / 🇺🇸 Parameter — Variable que una función recibe como entrada. El valor concreto que le pasas al llamarla se llama argumento.), hace su proceso interno (que no necesitas ver), y te devuelve una salida (el café = valor de retorno🇪🇸 Retorno / 🇺🇸 Return — Valor que una función devuelve a quien la llamó. La palabra clave return además termina la ejecución de la función.). Una vez que existe, no vuelves a "construir la cafetera": solo la usas.

# DEFINIR la función (construir la cafetera, se hace 1 vez)
def calcular_precio_final(precio, impuesto=0.16):
    """Devuelve el precio con impuesto incluido."""
    total = precio * (1 + impuesto)
    return round(total, 2)

# LLAMAR la función (usar la cafetera, las veces que quieras)
print(calcular_precio_final(100))        # 116.0 → usa el 16% por defecto
print(calcular_precio_final(100, 0.08))  # 108.0 → impuesto personalizado
// DEFINIR el método (en C# las funciones se llaman "métodos")
// double = tipo de dato que DEVUELVE
double CalcularPrecioFinal(double precio, double impuesto = 0.16)
{
    double total = precio * (1 + impuesto);
    return Math.Round(total, 2);
}

// LLAMAR el método (las veces que quieras)
Console.WriteLine(CalcularPrecioFinal(100));        // 116 → 16% por defecto
Console.WriteLine(CalcularPrecioFinal(100, 0.08));  // 108

Anatomía de una función

🏷️

Nombre

Debe decir QUÉ hace: calcular_total, no funcion1.

📥

Parámetros

Las entradas que necesita. Pueden tener valores por defecto.

⚙️

Cuerpo

Las instrucciones que se ejecutan al llamarla.

📤

Return

El resultado que devuelve (opcional: hay funciones que solo "hacen" sin devolver).

Alcance (scope): dónde "vive" cada variable

El alcance🇪🇸 Alcance / 🇺🇸 Scope — Región del código donde una variable existe y puede usarse. Las variables creadas dentro de una función solo existen dentro de ella. define dónde puede usarse una variable:

  • 🏠Local: nace dentro de una función y muere cuando la función termina. Como lo que escribes en un pizarrón de una sala de juntas: al salir, se borra.
  • 🌍Global: se declara fuera de toda función y todos la ven. Útil a veces, pero abusar de globales hace el código impredecible — los seniors las evitan.

¿Por qué usar funciones? (lo que evalúan los seniors)

  • ✅ Reutilizar: escribes la lógica una vez (principio DRY🇺🇸 DRY — Don't Repeat Yourself ("no te repitas"). Si copias y pegas el mismo código dos veces, probablemente debería ser una función.).
  • ✅ Leer: enviar_correo(cliente) se entiende solo.
  • ✅ Probar: puedes verificar cada función por separado.
  • ✅ Dividir problemas: un problema grande = varias funciones pequeñas.
  • 📏 Regla de oro: una función debe hacer UNA sola cosa y hacerla bien.

Módulo 5

Estructuras de Datos

Cómo organizar muchos datos: listas, diccionarios, tuplas y conjuntos.

📋 Listas: la fila de casilleros numerados

Una lista🇪🇸 Lista / 🇺🇸 List — Colección ordenada y modificable de elementos, donde cada uno tiene una posición (índice) empezando en 0. guarda varios valores en orden, cada uno con una posición llamada índice🇪🇸 Índice / 🇺🇸 Index — Posición numérica de un elemento dentro de una colección ordenada. En casi todos los lenguajes ¡empieza en 0, no en 1!. ⚠️ El primer casillero es el 0, no el 1 — el error más famoso de los principiantes.

tareas = ["estudiar", "ejercicio", "leer"]

print(tareas[0])          # "estudiar" → índice 0 es el PRIMERO
tareas.append("dormir")   # agregar al final
tareas.remove("leer")     # eliminar por valor
print(len(tareas))        # 3 → cuántos elementos hay
print(tareas[-1])         # "dormir" → -1 es el último (truco Python)
var tareas = new List<string> { "estudiar", "ejercicio", "leer" };

Console.WriteLine(tareas[0]);   // "estudiar" → índice 0 es el PRIMERO
tareas.Add("dormir");           // agregar al final
tareas.Remove("leer");          // eliminar por valor
Console.WriteLine(tareas.Count); // 3 → cuántos elementos hay
Console.WriteLine(tareas[^1]);  // "dormir" → ^1 es el último (C# 8+)

📖 Diccionarios: la agenda de contactos

Un diccionario🇪🇸 Diccionario / 🇺🇸 Dictionary — Colección de pares clave→valor. Buscas por la clave (como un nombre en tu agenda) y obtienes el valor (el teléfono) al instante. guarda pares clave → valor. No buscas por posición sino por clave, como buscas un teléfono por el nombre del contacto, no por "el contacto número 47".

producto = {
    "nombre": "Laptop",     # clave: "nombre" → valor: "Laptop"
    "precio": 15000,
    "disponible": True
}

print(producto["precio"])       # 15000 → acceso por clave
producto["precio"] = 13999      # modificar
producto["marca"] = "Dell"      # agregar clave nueva

for clave, valor in producto.items():
    print(f"{clave}: {valor}")
var producto = new Dictionary<string, object>
{
    ["nombre"] = "Laptop",    // clave: "nombre" → valor: "Laptop"
    ["precio"] = 15000,
    ["disponible"] = true
};

Console.WriteLine(producto["precio"]);  // 15000 → acceso por clave
producto["precio"] = 13999;             // modificar
producto["marca"] = "Dell";             // agregar clave nueva

foreach (var par in producto)
    Console.WriteLine($"{par.Key}: {par.Value}");

¿Cuál estructura uso? Tabla de decisión

Estructura🐍 Python#️⃣ C#Úsala cuando...

Arreglo(se usa list)int[] fijoTamaño fijo conocido de antemano (más eficiente).

Módulo 6

Errores y Excepciones

Los errores no son fracasos: son mensajes. Aprende a leerlos y a controlarlos.

Los 3 tipos de errores

1. De sintaxis

Escribiste mal el "idioma": falta un paréntesis, dos puntos, punto y coma. El programa ni siquiera arranca.

Analogía: una oración sin verbo — el lector se detiene de inmediato.

2. De ejecución (runtime)

La sintaxis es válida, pero al correr algo falla: dividir entre 0, abrir un archivo que no existe, índice fuera de rango. Lanzan una excepción🇪🇸 Excepción / 🇺🇸 Exception — Evento inesperado durante la ejecución que interrumpe el flujo normal del programa. Puede "atraparse" con try/catch para manejarlo con elegancia..

Analogía: la receta está bien escrita, pero el horno se descompuso a media cocción.

3. De lógica

El programa corre sin quejarse... pero da un resultado incorrecto. Usaste + en vez de -. Son los más difíciles de encontrar.

Analogía: el pastel se horneó perfecto... con sal en lugar de azúcar.

try / catch: el plan B de tu programa

Cuando una operación puede fallar (pedir datos al usuario, leer archivos, llamar a internet), la envuelves en un bloque protegido: "INTENTA esto; SI FALLA, haz esto otro en lugar de tronar".

try:
    texto = input("¿Cuántos años tienes? ")
    edad = int(texto)              # puede fallar si escriben "hola"
    print(f"En 10 años tendrás {edad + 10}")
except ValueError:                 # se ejecuta SOLO si hubo ese error
    print("Eso no es un número 😅")
finally:                           # se ejecuta SIEMPRE, falle o no
    print("Programa terminado")

# También puedes LANZAR tus propios errores:
def retirar(saldo, monto):
    if monto > saldo:
        raise ValueError("Fondos insuficientes")
    return saldo - monto
try
{
    Console.Write("¿Cuántos años tienes? ");
    string texto = Console.ReadLine();
    int edad = int.Parse(texto);   // puede fallar si escriben "hola"
    Console.WriteLine($"En 10 años tendrás {edad + 10}");
}
catch (FormatException)            // se ejecuta SOLO si hubo ese error
{
    Console.WriteLine("Eso no es un número 😅");
}
finally                            // se ejecuta SIEMPRE, falle o no
{
    Console.WriteLine("Programa terminado");
}

// También puedes LANZAR tus propios errores:
decimal Retirar(decimal saldo, decimal monto)
{
    if (monto > saldo)
        throw new InvalidOperationException("Fondos insuficientes");
    return saldo - monto;
}
📖 Vocabulario: Python dice try/except/raise; C# dice try/catch/throw. El concepto es idéntico: atrapar errores para manejarlos, o lanzarlos para avisar que algo salió mal.

Cómo leer un stack trace (sin pánico)

El stack trace🇺🇸 Stack Trace / 🇪🇸 Traza de pila — Reporte que muestra la cadena de llamadas que llevó al error: qué función llamó a cuál, y en qué línea exacta explotó. es el "reporte del accidente". Parece intimidante pero tiene 3 datos de oro:

  1. 1. El tipo de error — ValueError, NullReferenceException... dice QUÉ pasó.
  2. 2. El mensaje — la descripción humana del problema.
  3. 3. Archivo y línea — DÓNDE explotó. En Python, la última línea del trace es el error; en C#, la primera.

🐛 Kit de debugging del principiante

  • 🖨️ Prints estratégicos: imprime valores intermedios para ver dónde se tuerce el dato.
  • 🔴 Breakpoints: en VS Code / Visual Studio, pausa la ejecución en una línea y revisa cada variable en vivo. Nivel pro del print.
  • 🦆 Patito de goma: explica tu código en voz alta línea por línea (a un pato, a tu gato). El 50% de las veces encuentras el error tú misma al explicarlo.
  • ✂️ Divide y vencerás: comenta mitades del código hasta aislar la línea culpable.
